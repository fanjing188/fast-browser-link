# 无痕任务：能力与验收

`incognito: true` 选择浏览器的无痕/InPrivate 会话。默认普通任务保持原登录态。创建前和建窗时检查扩展无痕权限；普通和无痕任务分别复用窗口及任务，且拒绝跨上下文接管弹窗。

## 验收方式

使用 `tests/native-v2/real-incognito-matrix.mjs --package --headed`（Edge 加 `--edge`）和 `real-login-continuity.mjs`。每次创建临时 profile，仅访问本地合成页面。文件上传核对服务端收到的字节，下载核对任务归属及领取文件的 SHA-256；完整下载验收使用有界面的临时浏览器；本次 Chrome 的系统保存框已确认，Edge 无需额外确认，均使用测试目录和扩展建议的任务子目录。没有用 DevTools 替换下载委托或绕过归属事件。第三方页面的下载确认或保存提示仍可能需要用户处理。

## 边界

- 多个无痕任务共享该浏览器的无痕会话；需要账号间完全隔离时使用不同浏览器 profile。
- 无痕 Cookie 不继承普通 Cookie；普通 Cookie 镜像不会复制无痕登录态。
- 无痕不是“不留任何记录”：插件任务元数据和日志遵循原持久化规则，下载文件保存在磁盘上。
- 密码、支付、验证码仍由用户或可选私有 Vault 处理。本轮不提交真实支付，不解锁真实密码管理器，也不宣称所有 agent 框架版本已验证。
- 登录导航沿用剩余两分钟弹窗观察期，不无限延长；旧候选失效规则保留。页面面板展示最近五步，详细历史通过任务 get 的日志选项读取。
- `ref_click` 提供可信输入；DOM 合成点击不等同于用户手势，不能保证触发登录弹窗或浏览器下载。未知写入不重放，关闭弹窗造成回执失联时先确认页面是否已经关闭。
- 外部网站可能拒绝无痕模式、限制第三方 Cookie、要求验证码或额外权限。临时夹具通过不代表所有网站都能自动完成。
