# Page annotations, basket and execution risk

Page annotations are enabled by default. Settings → Interface offers compact (tier/pool/status) and full (also observed numbers/date) density. Detection reads visible keyword/domain/URL columns, report profile aliases/selectors, search queries/results and related questions. It never reads form values or hidden/editor content. A single closed-shadow overlay leaves the original page markup and layout intact, follows scroll/virtual row changes and ignores stale lookups. At most 300 objects are marked; larger pages use visible objects only. Owned Hermes/Fast-browser-link work tabs are excluded at both collection and request boundaries.

Labels use existing results, local cache and verified pool receipts. A zero is shown only when an actual source supplied zero. Small-site flags are displayed only when already supplied by a result/local rule; no public numeric cutoff is embedded. An optional `pool.lookup` binding may populate pool membership automatically only when explicitly zero-cost, local-only and read-only; it runs with a network/write-denying sandbox and a short deadline. Unclassified legacy lookup commands are not started by hover. Missing evidence remains unknown. No metric/authority provider query is launched by recognizing a page.

Use a label's `+`, selection popup, checked result rows or a confirmed table export to add to the work basket. A table can contribute all columns or explicitly selected columns. The basket persists privately under the selected runtime's Copilot data directory as `basket.json`; confirmed export references survive restart. Entries are grouped and deduplicated by normalized type/value/selected columns. Limits and text budgets reject oversized additions before changing the basket. Remove/clear are local reversible actions.

Batch check, expansion, trends, competitor analysis and pool save first produce a review screen: selected objects, one result task, pinned providers, batch sizes/call upper bounds, model-call upper count, rough token budget, and known duration or explicit unknown/call timeout budgets (excluding queue and human gates). These are estimates, not prices, completion deadlines or provider receipts. Scalar adapters run one object per call; batch adapters use their declared limit, capped at 100 for metrics and five for trend comparisons. Derived-domain calls are upper bounds. No agent-tool fallback is silently substituted into a batch. Registry fallback outside the reviewed providers is blocked. A changed basket, binding or expired review requires a new estimate.

Only confirmation starts a batch. An external-risk batch needs a separately issued second receipt. Paid work runs in owned background pages; current user tabs are unchanged. Batches share one judgment call at most, then use the configured local judge for tiers. Missing judge/metrics/authority stays explicit; no thresholds or tiers are fabricated. Trends preserve raw scope/series; previews show recent points and scope, with all series in the local artifact. One merged result card and per-batch logs record provider, returned results, skipped inputs and failures. Unavailable or unknown responses are not replayed. Stop prevents subsequent batches; already dispatched writes may need reconciliation. Incomplete results retain acquired evidence and require a fresh estimate for another batch.

New basket work is also recorded for the updater idle gate. Active/interrupted external work blocks upgrades; never delete a ledger or marker to bypass an unresolved outcome.

CSV/XLSX export and copy are local review actions. Export uses the configured TableStore export directory, formula-safe CSV and text cells in XLSX; no batch-supplied path is accepted. Large clipboard output is refused in favor of file export. Existing result-card batch/save and table-column actions also route through the review screen. Pool save can use a configured legacy command after confirmation and does not require model activation; accepted membership needs a real receipt.

## Extension contract

Templates, flows, steps and capability bindings may declare `risk: "zero" | "metered" | "external"`. Missing risk defaults to **metered**. Unknown cost and all agent/model paths are at least metered; `external: true` or `writes_outside_export_root: true` raises the risk to external. Risk is evaluated in the daemon, not accepted from inference output or page text.

A binding eligible for automatic reads additionally needs `cost: "zero" | "free" | "local"`, `read_only: true` and `local_only: true` for commands. Automatic local commands are sandboxed against network and writes outside their generated work directory; if that sandbox is unavailable they do not run. Browser readers additionally require `public: true` and `requires_login: false`, and cannot have a command query planner. MCP/agent fallbacks are never automatically invoked. Paid/unknown/login-required sources cannot become automatic by merely declaring `risk: "zero"`.

Model-free zero-cost extension flows must explicitly set `risk: "zero"`, `judgment: false`, and zero-risk steps backed only by eligible readers/transforms. A model step or an undeclared step prevents automatic execution. The built-in `local.lookup` primitive and valid cache hits are eligible without new external calls. Settings → Mode → “Automatically execute zero-cost actions” defaults on; turning it off keeps suggestions pending. Automatic cards/logs are labeled, and finishing a local/basket task does not trigger an additional completion-only inference call.

A capability may declare `estimated_seconds` for a review estimate. Per-tool credentials, domains, paid sources and business thresholds belong in local packs/configuration, never in public source. See [pack development](fbl-packs.md). Offline samples are synthetic DOM output, separate from installed Edge/browser/provider acceptance.
