# Fast-browser-link 2.6.0

2026-11-03，新版本候选。基于正式 2.5.1（2f07a7e）；本文件不代表已公开发布或个人安装已升级。

## 改动

- 新增 `wait_until`，统一元素、地址、响应、下载、弹窗的 any/all 等待，保留覆盖和事件基线。
- 新增 `run_steps`，整组参数与 CSS 预检、动作前监听、前后条件核验、首错停止；保留已送达回执，不重放未知动作。
- 新增 `diagnose_target`，只读返回当前范围的歧义、遮挡、禁用、只读和覆盖诊断，不创建写入资格。
- 名称定位等待固定原文档、租约及文档代次；当前范围不完整或有多个可操作同名目标时拒绝派发，遮挡只等待自然消失。
- 工作流截止后宿主可能仍在执行时，当前脚本阻止继续派发，仅显式核对可解除未知屏障。
- 新能力经绑定实例 `browser_workflow_v1` 检查；SDK、JSON CLI、MCP、Hermes 复用原脚本链。打包和安装要求携带 workflow 模块，缺件拒绝。

接口、限制和例子见 [通用工作流](../browser-workflows.md)。

## 验证范围

真实 Chrome/Edge 验收使用打包候选、本地合成页面、临时独立 profile 和私有 scratch。覆盖定位诊断、填写、响应与页面结果联合核验、后置失败停止、下载、导航、任意条件等待、超时及弹窗观察。SDK/CLI/MCP 接入另用本地临时浏览器验证；Hermes 路径通过实际脚本宿主与子进程验证。

效率对照保留三种写法：分散的三次脚本、原有单次批处理脚本、新组合接口。每种各三轮；结果不代表模型端到端、第三方网站或生产业务提速，也不证明新接口快于所有已有批处理写法。

离线回归覆盖条件组合、覆盖缺口、文档变化、事件缺口、事件基线、整组预检、实例/代次及旧能力拒绝、未知结果与传输截止不重放；实际通过情况以本次门禁报告为准。

## 安装与发布

本候选未执行个人安装、推送、打标签或公开发布。正式发行包需在后续发布流程生成并核验；升级必须同时更新宿主与扩展并重载。保留 2.5.1 的浏览器唤醒与任务归档能力，不以本次临时浏览器验收替代个人冷启动重连验收。
